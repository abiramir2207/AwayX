Billback Deviation Tolerance settings from Payables

 Blacksmith Applications, www.blacksmithapps.com

Where can I find this in FORGESM?

Settings > Payables >  Deviation Tolerance

URL Properties:  billbacks/settings/expectations.cfm

 

Use this page to set up your billback deviation tolerance settings.

 

Columns

Distributor Purchase Period Ratio: The purchase period and claim period may be different.  

Enter the number that represents the distributor purchase period ratio (note that the number you enter is set "to 1", i.e., if you enter 1, the ratio will be 1:1, if you enter 2, the ratio will be 2:1, and so on).

A 1:1 ratio means the distributor can billback for the same period of time that the program runs.

A 2:1 ratio means the distributor can billback for twice the period of time that the program runs.  For example, if the program is a one year program, a distributor can billback for 2 years in this scenario.

 

 

Distributor Purchase Period Offset: Enter the number of days that represents the difference between the start day of the program and the start day of the distributor's participation in the program. (In days)

For example, a program begins on July 1, but the distributor does not begin participating until August 15th.  

In this scenario, you might enter 45 as the number of offset days.  The distributor will be billing back only for the purchase period defined by the offset number of days rather than for the entire program period. The offset is how far back to verify that shipments actually were made to the distributor.

 

Usage Example:  A distributor is claiming for the month of July (7/1-7/31).

The program end date is 7/15.  Thus, the distributor should be paid for half of the volume they are claiming.  You could set the system to go back 15 days from the start date (offset) and 7 days from the end date for volume verification; the system would check invoices for 6/15 – 7/8 to verify the that the distributor actually purchased the product.

 

Billback Aggregation Period Ratio: This works like the Distributor Purchase fields above.  Enter the number of days during which the billbacks can be aggregated (rather than submitted individually) relative to the duration of the program.  The number you enter is set "to 1".

For example, if you enter 1, that means the billbacks can be aggregated for the same period of time that the program runs.

 

Billback Aggregation Period Offset: Like the Distributor Purchase fields, use this field to enter the number of days that represents the offset from the program start date after which you will allow billbacks from the distributor to be aggregated.

(In days)

The claim period and the program period may be different that is the ratio.  The offset is how far we go back to verify that shipments actually were made to the distributor.

 

So if a distributor is claiming for the month of July (7/1-7/31) and the program end dated on 7/15 then they should only get paid for half of the volume they are claiming for.  The system may be set to go back 15 days from the start date (off-set) and 7 days from the end date for volume verification so we would look at invoices for the dates of (I think) 6/15 – 7/8 to verify the distributor actually purchased the product.

 

Distributor Volume Tolerance: Enter the whole percent of volume tolerance that you will permit the distributor to vary from the program volume.

For example, if the program is for 1000 pounds, and you enter 10 percent as the volume tolerance, it means you're allowing the distributor to submit for 1100 pounds and that this is acceptable (because it is within a 10 percent variance of the program volume).

(Whole percent difference)

 

Rate Tolerance: Enter the whole percent that you will permit the distributor to deviate regarding the rate.  For example, if the program rate is 1.00, and you enter 10 percent as the percent for rate tolerance, the distributor can submit claims for anywhere from $0.90 to $1.10.

If you enter zero, it means you will accept billbacks for only the exact rate.

(Whole percent)

 

Click [Save Preferences] to save your entries or changes.
